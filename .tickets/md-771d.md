# Fix desktop auto-update configuration and separate it from CLI self-update

Installed Windows desktop app currently reports:

> update manifest URL is not configured; set DSP_UPDATE_BASE_URL, DSP_UPDATE_MANIFEST_URL, or Cargo package.repository

Runtime environment variables are not acceptable for `File > Check for Updates...`; desktop updater must work for non-technical users from packaged installation.

## Root Cause

`src-tauri/src/lib.rs` connects desktop File menu to updater built for standalone CLI self-update. URL resolution in `src-tauri/src/updater/manifest.rs` requires runtime env, compile-time `DSP_UPDATE_BASE_URL`, or Cargo repository metadata.

CLI release workflow embeds `DSP_UPDATE_BASE_URL`, but `.github/workflows/release-desktop.yml` does not. `src-tauri/Cargo.toml` also has no `package.repository`, leaving packaged desktop app without manifest URL.

Deeper issue: current `dsp-updates.json`, install-root checks, archives, and replacement behavior target CLI `dsp.exe`, not desktop installer/application. Merely setting URL in desktop build could make GUI consume wrong artifact.

## Design

- Separate desktop update flow from CLI self-update behavior.
- Define desktop-specific release manifest/artifacts for supported OS/architecture combinations, or use Tauri updater infrastructure if compatible with release process.
- Embed deterministic desktop update endpoint at build time; never require end-user environment variables.
- Configure `.github/workflows/release-desktop.yml` to generate/publish required signed desktop update metadata and assets.
- Add `repository` metadata to `src-tauri/Cargo.toml` only as sensible fallback; do not rely on it to distinguish CLI and desktop artifacts.
- Ensure desktop flow can never download or install CLI archive/`dsp.exe` as desktop update.
- Keep CLI self-update behavior working independently.
- Show user-friendly states from File menu: up to date, update available, download/install progress or safe browser/download action, network failure, malformed/signature-invalid manifest.
- If full desktop installation cannot be delivered safely in first slice, make menu perform safe desktop-specific check only; do not expose broken CLI updater.

## Acceptance Criteria

- Packaged Windows desktop app checks for updates without environment variables.
- Error about `DSP_UPDATE_BASE_URL`, `DSP_UPDATE_MANIFEST_URL`, or Cargo repository is never shown to installed GUI users.
- Desktop release workflow embeds deterministic endpoint and publishes matching desktop metadata/assets.
- Desktop update lookup selects correct OS, architecture, application artifact, and version.
- Desktop updater cannot select CLI artifacts or write to CLI install root.
- CLI update/check/self-update remains functional.
- File-menu errors use non-technical, actionable wording while technical details remain logged.
- Tests cover URL/config resolution, desktop-vs-CLI manifest isolation, platform asset selection, malformed/missing metadata, and no-update/update-available states.
- Windows release smoke test exercises `File > Check for Updates...` from packaged app without updater env vars.
- Update/release documentation describes desktop and CLI channels separately.
- Rust tests, frontend tests, typecheck, lint, and release workflow validation pass.

## Implementation Notes

- Added desktop-only update channel (`dsp-desktop-updates.json`) and manifest schema with `channel: desktop`, `desktop-*` targets, and `desktop-installer` artifacts.
- Desktop menu now performs safe check-only flow and no longer calls CLI self-update/install code.
- Desktop manifest rejects CLI-looking artifacts (`dsp`, `dsp.exe`, `dsp-*`) and non-desktop targets.
- Desktop workflow embeds `DSP_DESKTOP_UPDATE_BASE_URL`, builds separate macOS x64/ARM metadata targets, keeps matrix release uploads draft-only, validates complete final manifest/assets, then publishes after all jobs complete.
- Desktop update dialog now offers a functional `Open Release Page` action instead of static URL text.
- Desktop manifest validation now requires GitHub release URLs, supported desktop targets, matching artifact names, platform installer extensions, checksums, and non-CLI artifact names.
- Docs state current desktop updates are check-only; manifest signing/signature verification is required before any future auto-download or auto-install behavior.
- CLI self-update manifest/artifacts remain unchanged (`dsp-updates.json`).
